# Presenter and composite findings

`presentation-illustration-audit/composite-receipts.json` maps each current learner-bound illustrated hash to its exact source hash and records protected native windows. The receipt was written when its outputs were “unbound review candidates”; later learner bindings use those same hashes. This is a chronological label, not an unexplained asset substitution. The exact source/composite hashes match in all sixteen cases.

The source and final video streams are both 25 fps with identical frame counts for each lesson. Decoded audio is identical across every source/final pair. The repository's existing `validate-protected-windows.mjs` checked 44 protected presenter, countdown and closing samples against the current illustrated review files; minimum PSNR was 45.30 dB. The validator samples one midpoint per protected window. It does not prove every frame is smooth or every handoff is clean, so contextual native-source and final-composite playback remains a Phase 3 gate.

The recorded composite method copies source audio/subtitles and overlays the source video in native presenter and guided countdown windows. It replaces instructional stills outside those windows with project-local illustrations and bound approved-plate crops. No evidence in this pass shows a new provider render or a changed native presenter segment. The L01–L04 handoff correction receipt documents an earlier late-overlay blank-frame problem and a provider-free correction, but it covers older hashes for some lessons. Treat it as lineage, not a current visual approval. The prior 128-position presentation defect matrix is an issue inventory for Phase 3; this phase did not certify or repair those visuals.

L02–L04 have real presenter clips only at opening and closing, as their timelines state. Their very long silence is in the source audio, so protected presenter integrity does not cure the missing lesson narration. L01's protected branded end card occupies the silent tail, but the learner UI lacks an L01 end-screen binding. L16's UI end-screen interval is 0.087 s. Neither issue was changed.
