## `AGT-X-02`: The operating layer behind AMINA

Phase: teach
Recommended format: 6-post framework thread
CTA: soft pointer to Agentified, no provider link required

### Draft copy

1.

```text
AMINA is the operating loop I want around agentic work:

Align the job.
Map the source.
Instrument the receipt.
Negotiate the boundary.
Audit the result.

That is how speed becomes reviewable.
```

2.

```text
Align the job.

What is the agent actually being asked to do?

Who owns the outcome if the work is wrong?

If the job is vague, the output will sound confident and still miss the point.
```

3.

```text
Map the source.

Which packet, transcript, record, or approved brief is the agent allowed to use?

Most AI risk starts when the system can reach for context nobody meant to approve.
```

4.

```text
Instrument the receipt.

A team should be able to see what changed, what source was used, and what decision is waiting.

If the work cannot leave a receipt, it is hard to govern.
```

5.

```text
Negotiate the boundary.

Some actions can be drafted by AI.

Some actions need a human gate.

The system should know the difference before the work moves.
```

6.

```text
Audit the result.

Did the work improve the workflow, or did it just move faster?

That is the difference between automation and accountable automation.
```

### Amina rationale

This draft spells out AMINA on first use and gives each move one operating question. The public research supports a framework thread, but this version stays grounded in Agentified's source, boundary, gate, and receipt language.

### Moremi review

- Source-distance: Pass. It uses public framework-thread patterns but keeps the original AMINA language and operating questions.
- Privacy and rights: Pass. No third-party language, private records, screenshots, or proprietary visuals.
- Claim support: Pass. The acronym expansion matches the approved campaign brief.
- Escalation: Confirm the AMINA expansion remains final before provider handoff.
