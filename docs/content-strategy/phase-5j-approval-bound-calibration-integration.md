# Phase 5J: approval-bound calibration integration

`lib/attributable-calibration-integration.ts` is a pure bridge from exact Phase 5I shadow replay to the existing evidence-repair Human QA binding. It accepts caller-supplied retained fixtures, outcome receipts, the reporting policy, an expected report, an explicit integration decision, and a synthetic staging-shaped repair review. It recalculates the 5I report, verifies exact hashes and versions, and returns a deterministic internal captain-review candidate. The candidate includes the existing research-packet review path only when every gate passes. It neither loads that path nor writes a packet.

The integration decision is separate from the 5I outcome labels. It binds the complete report hash; reporting policy ID, version, and approval receipt; exact case, artifact and evidence versions; platform and format; cohort, performance, and source hashes; repair binding hash; authority identity and version; decision and expiry times; privacy and rights clearance; exclusions; provenance path; rollback procedure; and its own content hash. `authority_verified` must come from the owning approval store. A self-hashed synthetic receipt alone cannot establish real authority. This phase supplies no approval-store connector and can emit a ready candidate only for `synthetic_staging` with synthetic source fixtures.

The current repair binding must match the supplied binding exactly and pass the existing `repairBinding` hash convention. The review state must still be Human QA pending, unlinked, unchanged, fresh, privacy and rights cleared, with preparation and external execution disabled. The selected case must be scored and resolved; the group must be reportable under its versioned policy. Missing or changed source content, report, receipt, approval, source expiry, channel, format, or binding blocks the candidate. The report and source receipts remain read-only evidence; no label or policy is promoted.

The result has compile-time false locks for production writes, packet linkage, label promotion, notification, and external actions. Blocked results have no review path, provenance payload, or rollback action. Replay is deterministic and idempotent. The regression test uses only local synthetic fixtures shaped like historical records and an evidence-repair review binding. It makes no staging query or write, so there are no staging artifacts to clean up. No provider contact, credential, live collection, media, upload, schedule, publish, posting, outreach, or Slack path is included.

Next gate: the captain reviews the draft PR and synthetic result. A separate, explicit integration authorization and owning approval-store verification would be required before any real historical source, production packet, or Human QA workflow connection. That later work must preserve all existing production authorization, privacy, retention, and external-execution locks.
