# Portfolio app activation control plane

Status: Phase 4C-1 source candidate. Activation is disabled. This change does not create or configure a hosted Convex deployment, Vercel environment, Supabase migration, invitation, or consuming app integration.

## Ownership and boundary

Portfolio owns a separate Convex activation deployment. Trumpet Trainer's Convex deployment is never used. Supabase Auth remains Portfolio's adult identity authority. Convex owns app registration, adult interest and consent, invitation state, app grants, audit events, handoff codes, session handles, and distributed abuse budgets. No activation state is written to Supabase and no Convex table joins to `auth.users`. Portfolio's other Supabase features remain in place.

The Portfolio route verifies a current Supabase adult bearer with `verifyAuth` before redemption or handoff and checks the canonical account through the server-only Supabase Admin API before a Convex claim. The admin route verifies `verifyAdmin` before operator work. The anonymous interest route and app-server exchange/grant routes have no adult bearer by contract; they use exact origins or separate app server secrets and the bridge's distributed budget. The only public Convex surface is `POST /activation`, authenticated with a distinct 32+ character Portfolio bridge secret. It invokes internal functions with validators. The bridge secret never reaches a browser or an app. Token, code, handle, and abuse-key digests are computed on the Portfolio server; raw values never enter Convex, audit events, or operator read models.

The verified Supabase user ID is an opaque `externalSubject` string in Convex. `reviewed_by`, `redeemed_by`, `revoked_by`, `auth_user_id`, and `actor_user_id` from the withdrawn SQL model become this opaque audit or grant subject. The minimum identity snapshot is the normalized email at redemption, used to bind the invitation and invalidate access after an email change. It is not a profile copy. Interest email remains separate contact-consent data. No child identity is stored.

## Transaction and consistency model

Convex mutations atomically claim an invitation, create its grant, and append the redemption events. Operator transitions and audit events are in one Convex transaction. Handoff exchange atomically marks a code consumed and creates one handle. A failed or replayed claim creates no grant or second handle. Cross-app indexes bind all token, code, handle, and grant lookups to the app key. Expiry and revocation are checked at read time, with no sweep required for denial. An expired but unrevoked grant still blocks renewal; an operator must record an audited revocation, then review a new interest and invitation. Provider errors fail closed; callers do not receive token or bridge details.

Supabase verification and Convex mutation are sequential, not a cross-database transaction. If Supabase verification fails, no redemption or handoff write occurs. A Supabase account deletion or email change causes subsequent handle checks to fail closed through a fresh Admin lookup. Exchange also checks current identity before consuming a code. If identity changes between verification and the Convex mutation, a very short consistency window remains; the next access check denies it. No workflow requires atomic Supabase and Convex state. Operator revocation is immediately effective on the next Convex grant check.

A Portfolio logout must also end the consuming app's own verified adult session and discard its server-held handle. A handle is not a Supabase session and cannot prove logout on its own; without app session teardown, an already exchanged handle can remain usable until its 24-hour expiry while the account and email remain valid. This is an explicit consuming-app integration gate before activation. A deleted Supabase user, changed email, expired handle, revoked grant, or unavailable identity provider denies access. Do not claim immediate cross-app logout until that integration is tested.

## Existing HTTP contract

The Portfolio routes remain `/api/activation/interest`, `/redeem`, `/handoff`, `/handoff/exchange`, `/grant`, and `/api/admin/app-activation`. The `ActivationRepository` interface remains the server contract. Interest takes adult attestation, current contact-consent version, source receipt, and idempotency key. Redemption requires the first-party Portfolio origin and current adult Auth. Handoff returns a two-minute code in a URL fragment. The consuming app backend exchanges it once using its app-specific secret, binds the 24-hour opaque handle to its own adult session, and checks the grant server-side. A browser cannot exchange or check a grant. The operator route retains its explicit issuance switch and delivery adapter; provider-disabled delivery is the default. The synthetic local review fixture remains available only in development.

The 15-minute distributed budgets remain five interests, eight redemptions, twelve handoff issues, 120 exchanges, and 1,200 grant checks per HMAC key. A failed budget lookup rejects the request. Before activation, review retention for expired codes, handles, and budget rows; load-test concurrent budgets and one-use claims in a separately approved staging deployment.

## Configuration and rollout gates

The provider requires `APP_ACTIVATION_PROVIDER=convex`, `APP_ACTIVATION_ENABLE_WRITES=true`, a Portfolio-owned exact HTTPS `APP_ACTIVATION_CONVEX_SITE_URL`, `APP_ACTIVATION_CONVEX_BRIDGE_SECRET`, `APP_ACTIVATION_APP_ORIGINS`, `APP_ACTIVATION_CONSENT_VERSION`, `APP_ACTIVATION_DISTRIBUTED_ABUSE_ENABLED=true`, `APP_ACTIVATION_ABUSE_SECRET`, and Portfolio's Supabase URL, anon key, and service-role key. The Convex deployment must hold the matching `PORTFOLIO_ACTIVATION_BRIDGE_SECRET`. Handoff additionally requires `APP_ACTIVATION_HANDOFF_ENABLED=true` and distinct `APP_ACTIVATION_APP_SECRETS` per registered app. Issuance additionally requires `APP_ACTIVATION_ISSUANCE_ENABLED=true` and an approved delivery adapter. Every switch is absent by default. An app must be explicitly registered in Convex through the internal `registerApp` function after review; no public registration endpoint exists.

The three unlaunched activation-specific Supabase migrations and their SQL test were removed. There is no data migration in this phase because those tables were source-only. Confirm that fact against each hosted database before any future migration or deletion decision. The old Postgres activation URL and staging fallback are no longer accepted. Other Portfolio Supabase tables, Auth, and unrelated migrations are unchanged.

The official `npx convex codegen` command requires a selected Convex project. This development lane is prohibited from creating or configuring a hosted project, so generated bindings are intentionally absent from the commit. Before staging validation, the captain must provision the separate Portfolio-owned project under its own authorization, run official codegen, inspect and commit the generated bindings, and run Convex typecheck and a non-customer-data staging transaction matrix. Vercel – portfolio and Vercel – portfolio-staging are not configured or deployed for this provider. Keep recruitment, provider delivery, Adult Auth in the consuming app, billing, Stripe, and Anthropic disabled.
