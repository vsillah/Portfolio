## Exercise and model Operating File entry

**Prompt:** Create an Operating Map with one row per step and columns `trigger | role | tier | handoff | evidence`. Mark where the L01 job, L02 Decision Card, L03 sources and receipt, and L04 pending memory proposal sit. Add explicit closed paths for spending, sending, publication, and live execution. Circle one missing owner or evidence location.

**Harbor example:** `SYN-REQUEST-01` triggers a paper comparison. The classroom controller rule routes to the evidence-comparison role at **prepare only** tier. The role reads `SYN-ROOM-01`, `SYN-ATTEND-01`, and `SYN-FAC-01` under L03's classroom-only policy. A freshness failure produces `SYN-HOLD-01` for Morgan; otherwise `SYN-BRIEF-01` and its trace go to Morgan's review. Morgan owns the decision and may withdraw the draft with a dated reason. `SYN-PROP-01` stays pending in the memory lane; there is no approved shared memory. The evidence location is a **proposed classroom Operating File section**, not a live system. Spending, messages, booking, and public proof are closed.

**Claim map for source review:** The five columns and signal-to-delivery lifecycle come from Chapter 8. The stack-layer and missing-control prompts come from the workbook's “Operating Map.” Harbor roles, IDs, and closed paths are invented. The registered figure is a visual review candidate only, not evidence of this classroom stack.
